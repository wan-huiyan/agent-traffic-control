# Context routing does not grant authority

A routing result is a list of references, not an approval to execute tools, claim an
issue, create worktrees, push, merge, publish, deploy, or delete anything.

Preserve the host's permission system and all existing shipping gates, including
the separately installed resume-gate. Missing or interrupted verification is
unknown, not success. Reverify interrupted work before a shipping action.

Before parallel writers start, verify actual isolation parameters and distinct
worktree paths. A prompt asserting isolation is not evidence that isolation exists.
Before issue pickup, read live ownership and follow the established claim protocol.
Before shipping, verify the current revision and live state at the action boundary;
a cached route or old observation cannot certify either.

Respect manual-only skills and use the host's canonical skill loader for executable
procedures. Reading a skill file does not reproduce its tool permissions, forked
context, scripts, or hooks. Do not loosen those controls to satisfy a router.

Keep both sides of an unresolved conflict visible. A newer timestamp or a higher
relevance score does not establish truth or supersession. Missing required evidence
or a protected bundle that exceeds the budget needs explicit resolution, not silent
truncation. Router failure falls back to existing retrieval, never bulk loading.
