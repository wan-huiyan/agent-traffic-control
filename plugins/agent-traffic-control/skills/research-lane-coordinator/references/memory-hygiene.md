# Working with memory hygiene

The research loop improves decisions and experiments. Memory hygiene maintains the records that future sessions retrieve. They complement each other without either becoming a dependency for ordinary research.

## Exchange a small evidence packet

When memory-hygiene is installed and a relevant audit is requested, provide candidate corrections with their exact evidence, cause status, scope, canonical destination, superseded wording and revisit trigger. Ask it to check duplicate guidance, stale links, conflicting mechanisms, retrieval descriptions and feedback lifecycle. Keep experimental histories out of always-loaded indexes; link to the applicable evidence on demand.

For the memory-hygiene workflow that includes label integrity and mechanism-claim integrity, preserve these distinctions:

- A code-to-label mapping needs an authoritative source, not a guessed annotation.
- An asserted cause needs a way to re-derive it or an explicit uncertainty label.
- Description and index text must agree with the corrected body.
- Conflicting memories require evidence review; the newer one is not automatically correct.
- A missing audit helper means that check was skipped, not that the store is clean.

Read the installed skill's own instructions before invoking it. Resolve its location through the available catalog/runtime; do not hardcode a user's cache path or assume another host has Claude's memory layout. Report missing integrations and continue the core research work with its existing records.

## Avoid automatic promotion and scope creep

A keyword appearing in a rule store can suggest that feedback was incorporated; it does not prove the correction actually governs behavior. Verify the meaning and outcome before closing a correction. A matching identifier, a later timestamp or an arbitrary number of incidents is not enough to promote a hypothesis to a universal rule.

Follow the host's actual loading semantics and the project's own documentation layout. Do not import another tool's memory size limits, folder taxonomy or invocation hooks as universal facts. If memory hygiene proposes broad moves, deletions or resolution of conflicting owner instructions, honor its approval workflow and the user's existing authorization. This integration does not itself run that broad audit or grant permission to change unrelated memory.

Store personal/project evidence privately. Publish only generalized guidance with synthetic examples. Keep a single canonical correction with short pointers instead of identical instructions in the skill, memory index, handoff and runbook.

## Preserve useful freedom

Skills should supply missing context and observed failure mechanisms. They should not require fixed agent counts, mandatory models, a full review panel for every task, permanent bans inferred from one failure, or repeated confirmation for work already authorized. Leave room to choose a better method and document why it fits.

When evaluating a new rule, test a case where following it helps and a case where it could wrongly stop useful work. If it creates more overhead or refusals without a demonstrated benefit, shorten, narrow or remove it. Treat human-memory analogies and small local experiments as ideas to test, not proofs of model context limits. The goal is better work with less repeated error, not a larger instruction collection.
